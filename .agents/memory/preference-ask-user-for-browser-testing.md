对于需要人工操作浏览器的测试场景（点击按钮后观察 UI 变化、判断动画是否触发、检测弹窗内容、视觉验证等），**主动请求用户帮助而非自己用 `evaluate_script` 猜测**。

**适用场景**：
- 点击某个元素后需要视觉反馈判断是否生效（如按钮变 "打勾" 状态）
- 弹窗、Tooltip、Dropdown 等需要肉眼判断是否正确弹出/收起
- SVG 图标需要人工确认是否匹配某个特征（如复制 vs 分享图标）
- 多个类似元素需要区分优先级或位置关系
- DOM 结构过于庞大，用脚本遍历不如直接问用户

**参考做法**：直接说明需要用户做什么、看什么、注意什么，必要时提供最小测试脚本让用户在控制台运行，把输出贴回来。

而不是默默用 JS 探测大量特征再猜测——探测的轮次开销和复杂度过高，且容易误判。让用户看一眼往往 5 秒就能给出准确答案。
