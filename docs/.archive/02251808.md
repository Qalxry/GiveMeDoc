
## ~~P0-7 `renderTemplate()` 中 `String.replace()` 破坏内容中的 `$$` 数学块~~

`converter.ts` 的 `renderTemplate()` 使用字符串替换注入消息内容：

```typescript
// converter.ts — renderTemplate()
result = result.replace(/\{content\}/g, msg.content);
result = result.replace(/\{thinking_content\}/g, msg.thinkingContent);
```

JavaScript 的 `String.prototype.replace()` 对**替换字符串**（第二个参数）有特殊解释规则：

| 模式 | 含义 |
| --- | --- |
| `$$` | 插入字面 `$` |
| `$&` | 插入匹配到的子串 |
| `` $` `` | 插入匹配之前的文本 |
| `$'` | 插入匹配之后的文本 |
| `$n` | 插入第 n 个捕获组 |

因此，当 `msg.content` 包含 `$$...$$`（display math）时：

```
$$
\int_{-\infty}^{\infty} e^{-x^2} \, dx = \sqrt{\pi}
$$
```

会被输出为：

```
$
\int_{-\infty}^{\infty} e^{-x^2} \, dx = \sqrt{\pi}
$
```

同理，内容中的 `$&`、`` $` ``、`$'`、`$1`–`$9` 也会被意外解释。AI 回复（尤其是涉及 Shell/PHP/LaTeX 的内容）经常包含 `$` 符号，因此影响面较广。

**建议：** 将字符串替换改为函数式替换，避免特殊字符解释：

```typescript
result = result.replace(/\{content\}/g, () => msg.content);
result = result.replace(/\{thinking_content\}/g, () => msg.thinkingContent);
```

## ~~P1-11 多条消息导出时 `[citation:N]` 引用标记未清理~~

DeepSeek 的 AI 回复中可能包含 `[citation:6]`、`[citation:12]` 等引用标记（来源于搜索增强回答中的引用编号）。当前 `formatMarkdown()` 没有对应的清理逻辑：

```typescript
// converter.ts — formatMarkdown()
// 1. Inline math: \(...\) → $...$
// 2. Display math: \[...\] → $$...$$
// 3. Collapse excessive blank lines
// 4. Unify list bullets
// （无 citation 清理步骤）
```

**后果：** 导出的 DOCX 中会残留 `[citation:6]` 等无意义的文本片段，影响文档质量。

**建议：** 在 `formatMarkdown()` 中添加一步清理：

```typescript
// Remove citation references: [citation:N]
s = s.replace(/\[citation:\d+\]/g, '');
```

## ~~P1-12 多条消息导出中消息正文变为 H2 标题（最后一条除外）~~

多条消息导出时，用户/助手的消息正文在 DOCX 输出中变成了 H2 标题样式，但最后一条消息不受影响。

默认模板在每条消息前使用 `---` 作为分隔符：

```typescript
// types.ts — DEFAULT_CONFIG
userMessageTemplate: `---\n\n**用户：**\n\n{content}\n\n`,
assistantMessageTemplate: `---\n\n**助手：**\n\n> {thinking_content}\n\n{content}\n\n`,
```

**可能原因：**
1. Pandoc 的 `yaml_metadata_block` 扩展（默认启用）将文档中部的 `---` 解释为 YAML 元数据块起止符，导致消息内容被吞入元数据区域或格式异常。
2. 在特定内容拼接边界，`---` 被 Pandoc 解释为 Setext 风格的 H2 标题标记（当前一行文本与 `---` 之间无空行时）。
3. 上述行为仅影响非末尾消息，因为最后一条消息后无后续 `---` 触发此问题。

**建议：** 
- 将消息模板和消息中的 `---` 分隔符替换为更安全的替代方案（如 `***`，Pandoc 同样支持作为主题分隔线，且不会触发 YAML 元数据块解析）。
